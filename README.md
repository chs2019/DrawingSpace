DrawingSpace combines a Visio-style ribbon, searchable stencil pane, page tabs, rulers, and task panes with a real C# diagram editor. The browser application is **Uno WebAssembly with Skia rendering**, not a JavaScript mock-up or a screenshot of a desktop application. Native hosts use the same editing engine and controls.

> **Status: 0.2.0-alpha.1 feature branch.** The branch integrates Visio package interchange, a bounded ShapeSheet evaluator, document masters, semantic containers, rich text and direct connector editing. It does **not** claim complete Visio compatibility or pixel-identical UI. The public site above serves the last verified **main-branch** deployment; branch features are available in source and CI artifacts. See [compatibility](docs/compatibility.md) and [feature workflows](docs/advanced-workflows.md).

## What works

- **Direct editing:** stencil drag-and-drop and click insertion, marquee and multi-selection, movement, eight resize handles, rotation, inline shape and connector labels, snap-to-grid, dynamic alignment guides, undo/redo, clipboard, duplication, alignment, distribution, grouping, and stacking order.
- **Connected diagrams:** identity-based glued endpoints, straight and obstacle-aware orthogonal connectors, endpoint arrowheads, labels, AutoConnect shape insertion, and a deterministic automatic layout for directed graphs with a cycle fallback.
- **Document structure:** multiple named pages, page sizes and orientation, editable layers with independent visibility/locking/export inclusion, shape data, local comments, and basic diagram validation.
- **Reusable visual components:** custom command buttons, ribbon tabs/groups, vector icons, searchable stencil gallery, color palette, page strip, and a Skia drawing surface. Text entry, scrolling, sliders, combo boxes, and modal dialogs deliberately retain Uno platform primitives.
- **Original content:** 43 shape masters in five stencils—flowchart, basic shapes, network, organization, and containers/callouts—with editable purchase-approval, organization-chart, and network samples.
- **Local files:** validated native JSON open/save, SVG and PNG page export, multi-page PDF export, and shape-data CSV export. Browser recovery uses IndexedDB; native recovery uses an atomic local file replacement.

### Advanced workflows

The **Developer** ribbon opens ShapeSheet, Masters, Containers, Rich Text, Connections and Import Diagnostics. Formula changes, master edits, membership changes, range formatting, endpoint reattachment, waypoints and local comment replies participate in the same document transaction/undo system.

The **File** ribbon opens native JSON, VSDX, VSTX and VDX files. Opening VSSX merges a master library into the current drawing rather than replacing it. Visio export has explicit VSDX/VSSX/VSTX commands. Unsupported constructs remain visible in compatibility diagnostics; the reader never executes embedded code or fetches external relationships.

Connectors expose endpoint circles, waypoint squares and label diamonds. Drag an endpoint to glue or detach it; drag a hollow midpoint grip or Alt-drag a segment to insert a waypoint; Shift-click a waypoint to remove it. Moving a semantic container moves its members and internal connector waypoints together.

## Run from source

Install the SDK specified by [`global.json`](global.json). The pinned toolchain is .NET SDK **10.0.401**, Uno SDK **6.7.30**, and SkiaSharp **3.119.2**. The Uno SDK controls its compatible transitive platform dependencies; do not upgrade SkiaSharp independently without testing all hosts.

```bash
git clone https://github.com/wieslawsoltes/DrawingSpace.git
cd DrawingSpace
git switch feat/visio-parity

dotnet workload install wasm-tools --skip-manifest-update
dotnet run --project src/DrawingSpace.App -f net10.0-browserwasm
```

For native Windows, macOS, or Linux:

```bash
dotnet run --project src/DrawingSpace.App \
  -f net10.0-desktop -p:DrawingSpaceDesktopOnly=true
```

Native hosts require the usual Uno Platform prerequisites for the operating system. The desktop project uses Win32, macOS, X11, and Linux framebuffer host integrations. Mobile-native targets are not included in this release.

### Validate the production browser build

Node.js 22 is used only for acceptance tests, not for the application engine.

```bash
dotnet test tests/DrawingSpace.Tests -c Release

dotnet publish src/DrawingSpace.App -f net10.0-browserwasm -c Release \
  -o artifacts/publish -p:WasmShellWebAppBasePath=/DrawingSpace/
python3 scripts/collect-site.py artifacts/publish artifacts/site
npm ci
npx playwright install --with-deps chromium
python3 scripts/serve-site.py --directory artifacts/site --port 4173
```

In another terminal:

```bash
npm run test:browser
```

The browser suite drives actual pointer and keyboard input. Its opt-in `?test=1` diagnostics expose **read-only** geometry and control bounds; they do not inject edits or replace input handling. Tests cover startup and proportional fonts, stencil insertion, undo/redo, dragging, label editing, duplication, page operations, zoom, task panes, SVG download, recovery across a reload, formula editing, rich text ranges, masters, semantic containers, connector handles, and real VSDX/VSSX file pickers. Screenshots, console logs, and reports are uploaded by CI. Engine tests cover geometry, transforms, persistence, routing, transactions, validation, and Skia exports.

## Twelve reusable packages

| Package | Responsibility | Dependencies |
| --- | --- | --- |
| `DrawingSpace.Core` | Geometry, viewport, enums | .NET only |
| `DrawingSpace.Documents` | Model, pages, layers, validated JSON | Core |
| `DrawingSpace.ShapeSheet` | Bounded parser, dimensional values, lazy formula evaluation | .NET only |
| `DrawingSpace.Visio` | OPC package reader/writer, VDX reader, format detection | Documents, ShapeSheet, Editing |
| `DrawingSpace.Text` | HarfBuzz shaping, Unicode bidi/line breaking, paragraphs, range layout | Documents, SkiaSharp, HarfBuzzSharp |
| `DrawingSpace.Routing` | Orthogonal routing, custom endpoints, line jumps and route metrics | Documents |
| `DrawingSpace.Editing` | Transactions, selection, commands, snapping, validation | Routing |
| `DrawingSpace.Stencils` | Shape masters and original sample diagrams | Documents |
| `DrawingSpace.Skia` | Affine paths, shaped text, image cache, rendering, hit tests, exports | Routing, Text, SkiaSharp |
| `DrawingSpace.Controls` | Custom Uno ribbon, buttons, gallery, palette, page strip | Stencils, Skia, Uno |
| `DrawingSpace.Editor` | Embeddable interactive diagram surface | Controls, Editing |
| `DrawingSpace.Workbench` | Complete workspace and storage contract | Editor |

The nine headless libraries target `net10.0`; the three UI libraries target `net10.0-browserwasm` and `net10.0-desktop`. The application is a thin host, not a package dependency. Successful Build runs produce `.nupkg` and `.snupkg` files. Packages are **not assumed to be published to nuget.org**; use the CI/release artifacts as a local feed or run the explicit publishing workflow with your own feed credentials.

```bash
dotnet pack src/DrawingSpace.Editing -c Release -o artifacts/packages
dotnet pack src/DrawingSpace.Workbench -c Release -o artifacts/packages
```

### Embed the editor

```csharp
using DrawingSpace.Core;
using DrawingSpace.Documents;
using DrawingSpace.Editing;
using DrawingSpace.Editor;

var session = new EditorSession(new DiagramDocument { Title = "My diagram" });
var surface = new DiagramSurface { Session = session };

var first = new Shape { Text = "Receive", X = 100, Y = 100 };
var second = new Shape { Text = "Review", X = 340, Y = 100 };
session.AddShape(first);
session.AddShape(second);
session.Connect(first.Id, second.Id);

session.Select(first.Id);
session.MoveSelection(new PointD(16, 0));
session.Undo();

// Add surface to your Uno visual tree. Dispose it when the owning view closes.
```

For the complete UI, instantiate `DiagramWorkbench(session, storage)` with an implementation of `IWorkspaceStorage`. Implement the optional `IBinaryWorkspaceStorage` contract to enable Visio files without breaking existing JSON-only hosts. Headless consumers can use `EditorSession` without Uno, or `SceneRenderer` without the workbench. Supply the appropriate native SkiaSharp assets and configure renderer typefaces when embedding. The sample host loads regular, bold, italic, and bold-italic Open Sans faces from Uno's font package; it does not depend on Arial being installed in a browser.

## Persistence and exports

| Format | Read | Write | Boundary |
| --- | --- | --- | --- |
| `.drawingspace.json` | Yes | Yes | Editable versioned DrawingSpace model |
| SVG | No | Yes | Background-aware affine paths, outlined shape text with accessible labels, images and connector jumps |
| PNG | No | Yes | Background-aware current page; default 2×, bounded allocation |
| PDF | No | Yes | Foreground pages with inherited backgrounds; drawing pixels converted to points |
| CSV | No | Yes | Shape data; quoted fields and formula-prefix protection |
| VSDX / VSTX | Yes | Yes | Managed interchange subset, explicit compatibility diagnostics |
| VSSX | Yes | Yes | Document master libraries; import merges into the open drawing |
| VDX | Yes | No | Legacy XML interchange reader |
| VSD | No | No | Legacy binary format is not decoded |

The model uses 96 drawing pixels per inch. JSON import validates version, identities, references, geometry, styles, and size limits before replacing the current drawing. Recovery is a convenience, **not a backup system**: save important work to a native JSON file. Browser storage can be cleared or evicted, and clipboard access depends on browser permissions.

## Delivery workflows

**Build** runs engine tests, publishes the real Uno browser app, exercises it with Playwright, and builds all reusable NuGet packages. **Desktop** compiles native hosts on Windows, Linux, and macOS. **Pages** deploys only a successful main-branch Build artifact, verifies its source SHA, and runs the acceptance suite again against the public URL. **Release** publishes an exact validated Build's source, browser bundle, and packages as a GitHub prerelease or release. **Publish NuGet** is a separate opt-in workflow requiring `NUGET_API_KEY`.

`build-info.json` on the deployed site records the exact source commit. Compilation is not a claim that every native file picker, GPU, touch device, accessibility stack, or international script has been manually validated.
